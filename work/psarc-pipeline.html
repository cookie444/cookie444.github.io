PSARC Pipeline

A queue-driven pipeline that downloads, unpacks, and organizes a personal library of fan-made game add-on files from several different file hosts — triggered from a one-field form, fully containerized.

Stack
FastAPI, Redis, Postgres, Docker, n8n
Role
Solo build, design to deployment
Source
Private — walkthrough on request

The problem

I maintain a library of add-on files scattered across three different file hosts, each with its own login, anti-bot quirks, and download flow. Fetching anything meant babysitting browser tabs, re-entering credentials, and renaming files by hand.

I wanted one input — a link or an ID — and everything else automated: authentication, queuing, download, filename handling, storage, and a record of what happened.

How it works

One-field form
n8n webhook → API
FastAPI + nginx → Redis
job queue → Workers
async, scalable → Disk volume
organized output

Postgres tracks every job's status end to end.

A tiny local web page posts a JSON payload to an n8n webhook, which hands it to the API. The API validates the request, records it in Postgres, and pushes a job onto a Redis queue. Workers block on the queue, fetch the file from whichever host it lives on (Google Drive, MediaFire, and a couple of direct hosts), and stream it to a shared volume with its real filename pulled from the response headers.

Under the hood

Exactly-once workers. Jobs are claimed with Redis BLPOP, which is atomic — so you can run two or ten workers and each job still gets processed exactly once, with no locking code to maintain.

One authenticated session, reused. Hosts that require login get a persistent session object shared by every downloader, so the pipeline authenticates once and stays authenticated.

Files land with their real names. Hosts hide filenames behind opaque IDs, so the downloader reads Content-Disposition headers and falls back gracefully when a host sends nothing:

def get_filename(resp, default="file.bin"):
    cd = resp.headers.get("content-disposition", "")
    if cd:
        m = re.search(r"filename\*?=(?:UTF-8'')?([^;\n]+)", cd)
        if m:
            return m.group(1).strip().strip('"')
    return default

Downloads stream to disk in 8 KB chunks, so multi-hundred-megabyte files never touch memory.

What broke

The honest part of any build. I keep a WORKAROUNDS.md in the repo with every issue hit during development. A few favorites:

  • Containers died on import. A shared dependency was installed locally but never added to requirements.txt — the fix was boring, but it's why every service now builds clean from scratch.
  • "Module not found" inside Docker. The working directory wasn't on the Python path; one ENV PYTHONPATH=/app line in each Dockerfile fixed it.
  • A Python 3.12 upgrade broke the worker. asyncio.wait_for() dropped its loop= parameter. Updating to current patterns instead of pinning an old Python kept the stack upgradeable.

None of these are exotic. That's the point — a deployment that survives the boring failures is the one you can actually trust.

What I'd do next

Retry with exponential backoff per host, a small web UI to watch job status live (the data's already in Postgres), and dead-letter handling for jobs that fail three times. The queue makes all three cheap.
